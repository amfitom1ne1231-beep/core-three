# Запуск на сервере

Один VPS в России, всё в Docker (`docker-compose.yml` в корне):

| Адрес | Что |
|---|---|
| `corethree.ru` | сайт |
| `www.corethree.ru` | переадресация на `corethree.ru` |
| `bot.corethree.ru` | сервис бота: webhook Telegram, мини-приложение `/app/`, его API |

Caddy сам получает и продлевает сертификаты. Postgres хранит базу
в томе, раз в сутки копия ложится в `/opt/corethree/backups` (две недели).
Образы собираются на этой машине под процессор сервера, сервер их только
запускает — хватает тарифа с 1–2 ГБ памяти.

Проверено целиком на этой машине 04.10.2026 (тот же compose на
`localhost`): сайт, сервис, мини-приложение, заявка с формы «Мы напишем
сами» дошла до Postgres с пометкой `help`, копия базы создалась.

## Что нужно

- VPS: Ubuntu 24.04, 1–2 ГБ памяти, от 20 ГБ диска.
- SSH-ключ `~/.ssh/corethree_vps` (на машине разработчика) — открытая
  часть добавлена на сервер при создании. Пароль сервера не нужен.
- Домен `corethree.ru` — в REG.RU, записи там же.

Дальше `SERVER=root@<ip>` — адрес сервера.

## 1. Подготовить сервер (один раз)

```
SERVER=root@<ip> deploy/setup.sh
```

Docker из репозиториев Ubuntu, подкачка 2 ГБ, файрвол (SSH, 80, 443),
вход только по ключу.

## 2. Записи домена в REG.RU

«Домены» → `corethree.ru` → «DNS-серверы и управление зоной»:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | IP сервера |
| A | `www` | IP сервера |
| A | `bot` | IP сервера |

Старые A-записи на `@` и `www` (заглушка REG.RU) — удалить. Записи
расходятся от нескольких минут до пары часов; проверка:
`dig +short corethree.ru` показывает IP сервера.

## 3. Секреты

```
SERVER=root@<ip> GROUP_THREAD_ID=<тема «Заявки»> deploy/secrets.sh
```

Берёт настройки, с которыми бот и сайт работают сейчас (`bot/.env.local`
и `.env.local` основной папки), и кладёт на сервер `.env`,
`deploy/bot.env`, `deploy/site.env` с правами 600. Новые — только пароль
базы и `WEBHOOK_SECRET`. Значения на экран не выводятся.

`GROUP_THREAD_ID` — номер темы «Заявки» в группе: в настройках его нет,
привязка `/bind` лежит в базе разработки. Без него карточки пойдут
в «Общую» тему — тогда после запуска отправить `/bind` в теме «Заявки».

## 4. Остановить бота на этой машине

Один токен — один бот: пока здесь работает снимок с туннелем
(`corethree-bot-live`), сервер получит конфликт. Остановить его перед
выкладкой.

## 5. Выложить

```
SERVER=root@<ip> deploy/push.sh
```

Собирает образы, отправляет их на сервер, перезапускает. Им же —
каждое следующее обновление сайта или бота. Счётчик Метрики, когда
появится: `NEXT_PUBLIC_YM_ID=<номер> SERVER=… deploy/push.sh`.

## 6. Проверить

- `https://corethree.ru` открывается, замок в адресной строке;
- `https://bot.corethree.ru/health` → `{"ok":true}`;
- заявка с сайта приходит карточкой в тему «Заявки»;
- в личке бота кнопка «Студия» открывает мини-приложение.

Логи: `ssh … 'cd /opt/corethree && docker compose logs -f bot'`
(или `site`, `caddy`).

## После запуска

- **База начинается с чистого листа.** Владельцы входят сами
  (`OWNER_TG_IDS`), группа — из `GROUP_CHAT_ID`; остальным участникам —
  новая ссылка `/invite`. Заявки из базы разработки — тестовые.
- **Мини-приложение напрямую из группы:** у @BotFather задать Main Mini
  App `https://bot.corethree.ru/app/`, в `deploy/bot.env` —
  `MINI_APP_LINK=direct`, перезапуск.
- **Политика:** дописать место хранения — сервер в России
  (`content/legal.ts`, раздел «Хранение и защита»).
- **Роскомнадзор:** уведомление об обработке персональных данных
  подаётся до того, как форма начнёт принимать заявки.

## Копии базы

Лежат на сервере в `/opt/corethree/backups/corethree-<дата>.sql.gz`.
Следующий шаг — уносить их в облачное хранилище в РФ: копия на том же
диске не спасёт от потери сервера.

Восстановить (в пустую базу):

```
cd /opt/corethree
docker compose stop bot
docker compose exec -T db psql -U corethree -d postgres -c 'DROP DATABASE corethree' -c 'CREATE DATABASE corethree OWNER corethree'
gunzip -c backups/corethree-<дата>.sql.gz | docker compose exec -T db psql -U corethree -d corethree
docker compose start bot
```
