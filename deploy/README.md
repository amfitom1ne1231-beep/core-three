# Запуск на сервере

Один сервер в России — Yandex Cloud (или любой VPS), всё в Docker
(`docker-compose.yml` в корне):

| Адрес | Что |
|---|---|
| `corethree.ru` | сайт |
| `www.corethree.ru` | переадресация на `corethree.ru` |
| `bot.corethree.ru` | сервис бота: webhook Telegram, мини-приложение `/app/`, его API |

Caddy сам получает и продлевает сертификаты. Postgres хранит базу
в томе, раз в сутки копия ложится в `/opt/corethree/backups` (две недели).
Образы собираются на машине разработчика под процессор сервера, сервер
их только запускает — хватает 2 ГБ памяти.

Проверено на машине разработчика 05.10.2026 теми же образами: сайт,
сервис и Postgres вместе, заявка с формы дошла до базы — в том числе
когда Telegram с сервера недоступен; лимит заявок за Caddy не обходится
подменой заголовка. На настоящем сервере ещё не запускалось.

## Что нужно

- Сервер: Ubuntu 24.04, 2 ГБ памяти, от 20 ГБ диска.
- SSH-ключ `~/.ssh/corethree_vps` (на машине разработчика) — открытая
  часть (`corethree_vps.pub`) добавляется на сервер при создании.
- Домен `corethree.ru` — в REG.RU, записи там же.

Дальше `SERVER=<логин>@<ip>` — логин, заданный при создании машины,
и её публичный адрес. В Yandex Cloud входа под `root` нет; у обычного
VPS это `root@<ip>`. Скрипты работают в обоих случаях.

## 0. Yandex Cloud: создать машину

В консоли `console.yandex.cloud` (нужен платёжный аккаунт; новому
аккаунту даётся стартовый грант — его хватает примерно на два месяца
такой машины).

1. **Compute Cloud → создать виртуальную машину.**
   - образ: Ubuntu 24.04 LTS;
   - диск: 20 ГБ (SSD быстрее, HDD дешевле — базе хватит и HDD);
   - платформа Intel Ice Lake, 2 vCPU, гарантированная доля 20%,
     память 2 ГБ; **не** прерываемая — прерываемую облако выключает
     раз в сутки;
   - публичный адрес: автоматически;
   - доступ: логин — например `corethree`; SSH-ключ — содержимое файла
     `~/.ssh/corethree_vps.pub`.

   Такая машина стоит около полутора тысяч рублей в месяц вместе
   с адресом; точную цифру консоль показывает до создания.
2. **Сделать адрес статическим.** Virtual Private Cloud → IP-адреса →
   у адреса машины «Сделать статическим». Иначе после остановки машины
   адрес сменится, и записи домена придётся править.
3. **Проверить порты 80 и 443.** Virtual Private Cloud → Группы
   безопасности → группа сети машины. Если во входящих правилах стоит
   `0.0.0.0/0`, протокол `Any` — открыто всё, делать ничего не нужно
   (так было у облака CoreThree; лишнее закрывает файрвол на самой
   машине). Если открыт только SSH — добавить входящие правила: TCP 80,
   TCP 443, UDP 443 от `0.0.0.0/0`. Без них сайт не откроется и Caddy
   не получит сертификат, хотя на самой машине всё будет работать.
4. **Снимки диска по расписанию.** Compute Cloud → Снимки дисков →
   расписание: раз в сутки, хранить неделю. Это копия всего сервера
   вместе с базой — на случай потери машины.

Проверка: `ssh -i ~/.ssh/corethree_vps <логин>@<ip>` пускает без пароля.

**Машина CoreThree создана 05.10.2026:** `corethree@81.26.183.159`
(адрес статический), зона `ru-central1-d`, 2 vCPU 20%, 2 ГБ, 20 ГБ SSD —
1 700 ₽ в месяц по счёту консоли. Cloud Backup и снимки по расписанию
не включены. Telegram с неё ненадёжен: отдельные соединения проходят,
остальные нет — для работы группы нужен ретранслятор.

## 1. Подготовить сервер (один раз)

```
SERVER=<логин>@<ip> deploy/setup.sh
```

Docker из репозиториев Ubuntu, подкачка 2 ГБ, файрвол (SSH, 80, 443),
вход только по ключу. Последняя строка вывода — достаёт ли сервер
до Telegram: от неё зависит раздел «Telegram с российского сервера».

## 2. Записи домена в REG.RU

Можно отложить: пока домен не указывает на сервер, `push.sh` открывает
сайт по адресу машины — `http://<ip>`, без HTTPS, закрытым от поиска
(`deploy/Caddyfile.ip`). Это только для своей проверки: заявки идут
открытым текстом, сервис бота наружу закрыт, а сам бот вместо webhook
опрашивает Telegram (строка `BOT_MODE=polling` в `.env` на сервере).
Как только записи на месте, следующий `push.sh` сам включает основной
`Caddyfile`, сертификаты и webhook.

«Домены» → `corethree.ru` → «DNS-серверы и управление зоной»:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | IP сервера |
| A | `www` | IP сервера |
| A | `bot` | IP сервера |

Старые A-записи на `@` и `www` (заглушка REG.RU) — удалить. Записи
расходятся от нескольких минут до пары часов; проверка:
`dig +short corethree.ru` показывает IP сервера.

## 3. Секреты

```
SERVER=<логин>@<ip> GROUP_THREAD_ID=<тема «Заявки»> deploy/secrets.sh
```

Берёт настройки, с которыми бот и сайт работают сейчас (`bot/.env.local`
и `.env.local` основной папки), и кладёт на сервер `.env`,
`deploy/bot.env`, `deploy/site.env` с правами 600. Новые — только пароль
базы и `WEBHOOK_SECRET`. Значения на экран не выводятся.

`GROUP_THREAD_ID` — номер темы «Заявки» в группе: в настройках его нет,
привязка `/bind` лежит в базе разработки. Без него карточки пойдут
в «Общую» тему — тогда после запуска отправить `/bind` в теме «Заявки».

Google-таблица на сервер не переносится: копия заявок на серверах Google —
передача персональных данных за границу, для неё нужно отдельное
уведомление в Роскомнадзор. Включить осознанно —
`WITH_SHEETS=1 SERVER=… deploy/secrets.sh`.

## 4. Остановить бота на этой машине

Один токен — один бот: пока здесь работает снимок с туннелем
(`corethree-bot-live`), сервер получит конфликт. Остановить его перед
выкладкой.

## 5. Выложить

```
SERVER=<логин>@<ip> deploy/push.sh
```

Собирает образы, отправляет их на сервер, перезапускает. Им же —
каждое следующее обновление сайта или бота. Счётчик Метрики, когда
появится: `NEXT_PUBLIC_YM_ID=<номер> SERVER=… deploy/push.sh`.

Сборка под процессор сервера идёт в эмуляции и изредка падает сама
по себе: сайт — на загрузке шрифтов с Google Fonts (`next/font`), бот —
на установке зависимостей. Скрипт повторяет каждую сборку до трёх раз.

## 6. Проверить

- `https://corethree.ru` открывается, замок в адресной строке;
- `https://bot.corethree.ru/health` → `{"ok":true}`;
- заявка с сайта приходит карточкой в тему «Заявки»;
- в личке бота кнопка «Студия» открывает мини-приложение.

Логи: `ssh … 'cd /opt/corethree && docker compose logs -f bot'`
(или `site`, `caddy`).

Если сервер не может скачать `caddy` или `postgres` с Docker Hub —
в `/etc/docker/daemon.json` прописать зеркало
(`{"registry-mirrors": ["https://mirror.gcr.io"]}`) и перезапустить Docker.

## Telegram с российского сервера

Telegram в России заблокирован, и с сервера в российском дата-центре
`api.telegram.org` может не отвечать. Проверка (её же делает `setup.sh`):

```
ssh -i ~/.ssh/corethree_vps <логин>@<ip> 'curl -m 10 -sS -o /dev/null -w "%{http_code}\n" https://api.telegram.org'
```

`302` — доступен, делать ничего не нужно. Таймаут — нужен ретранслятор.

**Что работает без Telegram.** Сайт принимает заявки, сервис кладёт их
в базу и отвечает сайту сразу — человек ошибки не видит. Мини-приложение
открывается. Не работают карточки в группе, кнопки под ними, напоминания
и сводки. В логе сервиса — `[bot] подключение к Telegram не удалось, повтор через …`:
он пробует снова сам. Когда связь появится, карточки заявок за последние
двое суток встанут в группу без чьего-либо участия.

**Ретранслятор** — свой маленький сервер за границей, который пересылает
запросы в Telegram. Достаточно Caddy с таким файлом (свой домен вместо
`tg.example.com`):

```
tg.example.com {
	reverse_proxy https://api.telegram.org {
		header_up Host {upstream_hostport}
	}
}
```

Его адрес — в обе настройки на сервере, `deploy/bot.env` и `deploy/site.env`:

```
TELEGRAM_API_ROOT=https://tg.example.com
```

затем `cd /opt/corethree && docker compose up -d`. Токен бота идёт
в адресе каждого запроса, поэтому ретранслятор — только свой сервер:
чужой «бесплатный прокси для ботов» получит токен целиком.

**Если карточки приходят, а кнопки под ними молчат** — до сервера
не доходят входящие от Telegram. Тогда сервис опрашивает Telegram сам:
в `/opt/corethree/.env` добавить строку `BOT_MODE=polling`
и `docker compose up -d`.

## После запуска

- **База начинается с чистого листа.** Владельцы входят сами
  (`OWNER_TG_IDS`), группа — из `GROUP_CHAT_ID`; остальным участникам —
  новая ссылка `/invite`. Заявки из базы разработки — тестовые.
- **Мини-приложение напрямую из группы:** у @BotFather задать Main Mini
  App `https://bot.corethree.ru/app/`, в `deploy/bot.env` —
  `MINI_APP_LINK=direct`, перезапуск.
- **Роскомнадзор:** уведомление об обработке персональных данных
  подаётся до того, как форма начнёт принимать заявки; о передаче данных
  за границу (карточки заявок в Telegram) — отдельное. Что именно сказано
  в политике и что остаётся юристу — `HANDOFF.md`, «Документы».
- **Проверить `SITE_NOINDEX`:** на сервере его быть не должно —
  `curl -sI https://corethree.ru | grep -i robots` ничего не выводит.

## Копии базы

Лежат на сервере в `/opt/corethree/backups/corethree-<дата>.sql.gz`.
От потери самого сервера они не спасают — для этого снимки диска
по расписанию (раздел 0, шаг 4). Следующий шаг — уносить и сами копии
в Yandex Object Storage.

Восстановить (в пустую базу):

```
cd /opt/corethree
docker compose stop bot
docker compose exec -T db psql -U corethree -d postgres -c 'DROP DATABASE corethree' -c 'CREATE DATABASE corethree OWNER corethree'
gunzip -c backups/corethree-<дата>.sql.gz | docker compose exec -T db psql -U corethree -d corethree
docker compose start bot
```
