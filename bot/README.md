# Сервис бота CoreThree

Что это и зачем — `BOT.md` в корне. Здесь — как запустить.

```
cd bot
npm install
cp .env.example .env.local   # вписать BOT_TOKEN, OWNER_TG_IDS, INTAKE_SECRET
npm run dev                  # бот (polling), HTTP :8787, расписание
npm test                     # тесты на встроенном Postgres, без Docker
npm run typecheck
npm run build && npm start   # сборка в dist/main.js
```

Сайт отправляет заявки сюда, если у него заданы `BOT_INTAKE_URL`
(`http://localhost:8787/api/intake/lead`) и тот же `INTAKE_SECRET`.

## Первый запуск с настоящим ботом

1. @BotFather → `/newbot` → токен в `BOT_TOKEN`.
2. Telegram id владельцев (свой покажет @userinfobot) — в `OWNER_TG_IDS`
   через запятую.
3. `npm run dev`, каждый пишет боту `/start` — и он в команде.
4. Рабочая группа: добавить бота **администратором** с правом удалять
   сообщения — тогда он убирает за собой просьбы «ответьте заметкой».
   В группе с темами — завести тему «Заявки» и отправить `/bind` в ней;
   без этого карточки идут в общую тему (`GROUP_CHAT_ID` из окружения
   задаёт группу без темы).
5. Остальным — ссылку из `/invite` в личке бота.

## Мини-приложение

Исходники — `admin/` (свой `package.json`), сервис отдаёт сборку
по `/app/`, а её API — `/api/app/*` (вход по подписи Telegram).

```
cd admin && npm install
npm run dev      # в браузере: http://localhost:5173/app/, API — у сервиса на :8787
npm run build    # admin/dist — её сервис и отдаёт
```

В браузере Telegram нет, поэтому в `bot/.env.local` нужен `APP_DEV=1`:
сервис пускает запросы с этой же машины от имени первого владельца.

В самом Telegram приложение открывается только по HTTPS. Пока сервера
нет — туннель:

```
brew install cloudflared     # один раз
cd bot && npm run dev:tunnel # вместо npm run dev
```

Сервис получает временный адрес (новый при каждом запуске), ставит
команде кнопку меню «Студия» в личке бота и «Открыть» под карточками
в группе. Сервис в это время виден из интернета; всё, что он отдаёт
наружу, закрыто подписью.

## Живой бот и разработка

Правки в исходниках перезапускают `npm run dev` и `dev:tunnel`, а новая
миграция применяется при первом же перезапуске. Чтобы бот оставался
в сети и настоящая база не менялась раньше времени:

```
npm run start:tunnel   # снимок: собранный сервис и приложение + туннель
npm run demo           # отдельно: сервис без бота на :8788, выдуманные данные
cd ../admin && npm run dev:demo   # приложение на :5174 против демо-сервиса
```

Демо-база (`.data/demo`) пересоздаётся при каждом запуске из
`scripts/seed.ts`: команда из троих, заявки на всех этапах, проекты
с задачами, сроками, материалами и доступами. Настройки демо — `.env.demo`,
секретов в нём нет.

Перед перезапуском снимка с новой миграцией — копия папки базы
(`BOT_DATA_DIR`) при остановленном сервисе.

## Google-таблица

Бот раз в минуту дублирует в таблицу заявки (с именами и контактами),
историю действий, проекты, задачи и итоги по неделям — каждое на своём
листе. Таблица — отражение базы для глаз: из неё бот ничего не читает,
правки в его колонках перезапишутся. Свои колонки с пометками можно вести
правее — строки находятся по номеру в первой колонке и не съезжают.
Доступов (паролей) в таблице нет, только их названия в истории.

Пишет в таблицу её собственный скрипт (`sheets/Code.gs`), а бот шлёт ему
строки с общим секретом. Сервисный аккаунт Google не нужен.

На боевом сервере таблица выключена: контакты клиентов у Google — передача
персональных данных за границу, в политике сайта о ней не сказано.
Включать — только вместе с текстами и уведомлением в Роскомнадзор
(`deploy/README.md`, «Секреты»).

1. В `bot/.env.local` — `SHEETS_SECRET` (`openssl rand -hex 32`).
2. `npm run sheets:script` — готовый скрипт с секретом ляжет
   в `bot/.data/sheets-script.gs` (в git не попадает).
3. Новая таблица в Google → Расширения → Apps Script → заменить всё
   содержимое `Code.gs` этим файлом → сохранить.
4. Развернуть → Новое развёртывание → тип «Веб-приложение»; запуск —
   от своего имени, доступ — «Все». Google попросит разрешить скрипту
   работу с таблицей и предупредит, что приложение не проверено: это ваш
   же скрипт — «Дополнительные настройки» → «Перейти». Адрес вида
   `https://script.google.com/…/exec` — в `SHEETS_URL`.
5. Перезапустить сервис: в логе `[sheets] дублирование в таблицу включено`,
   через несколько секунд — `в таблицу ушло строк: …`. Первая выгрузка —
   всё сразу, дальше — только изменившиеся строки.

Если `sheets/Code.gs` поменялся — снова шаги 2–3, затем Развернуть →
Управление развёртываниями → карандаш → версия «Новая»: так адрес
остаётся прежним (новое развёртывание дало бы новый).

Таблица недоступна — бот повторит через пять минут, ничего не потеряв
и не задвоив. Удалённое в таблице руками бот не восстанавливает: заявка,
проект или задача вернутся, когда изменятся в базе, событие истории — нет.
Итоги недель пересчитываются за последние двенадцать недель; более
старые остаются в таблице как были.

## Рабочие копии

Настройки и база разработки — в основной папке; в рабочей копии
`.claude/worktrees/*` на них ставятся ссылки (`BOT.md`, «Запуск
в рабочей копии»). `BOT_DATA_DIR` там — полный путь: база одна на всех,
и открыть её может только один запущенный сервис.

## Устройство

- `src/domain` — заявки, проекты (этапы, задачи, материалы, доступы),
  метрики и сводки, команда, сроки, рабочее время. Без Telegram и HTTP, поэтому проверяется
  тестами на любых часах
- `src/tg` — бот (grammY): карточки, кнопки, заметки, напоминания
- `src/http` — Hono: приём заявок с сайта, webhook Telegram,
  вход и API мини-приложения, его статика
- `src/jobs` — расписание: напоминания, вечерняя тревога, утренняя
  сводка и итоги недели
- `src/sheets` — дублирование в Google-таблицу: что уходит (`rows.ts`)
  и как отправляется только разница (`sync.ts`); скрипт самой
  таблицы — `sheets/Code.gs`
- `src/db` — схема Drizzle; миграции в `drizzle/`, генерируются
  `npm run db:generate`, применяются при старте
