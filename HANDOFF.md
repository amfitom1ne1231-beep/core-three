# CoreThree — передача работы

Состояние на 5 октября 2026 года. Сайт студии свёрстан целиком и работает
локально; до запуска не хватает подключений (заявки, хостинг, домен,
счётчик) и нескольких правок по сайту. История решений — в `BRIEF.md`:
он длинный, но каждый проход там записан с причинами. Последние решения
заказчика — разделы 28 и 29.

## С чего начать

```
npm install
npm run dev          # разработка, порт 3000
npm run build:check  # боевая сборка в .next-check
npm run start:check  # она же на порту 3100 (или на PORT, если задан)
```

Проверки перед коммитом: `npm run lint`, `npx tsc --noEmit`, `npm test`.
Те же проверки — в GitHub Actions на каждый пуш (`.github/workflows/ci.yml`).

Рабочий бот студии — отдельное приложение в `bot/`, его мини-приложение
в Telegram — `admin/`; у каждого свои зависимости. План, состояние
и что делать дальше — `BOT.md` (раздел «Передача»), запуск —
`bot/README.md`.

сообщение прямо в группу (`lib/notify.ts`).

## Как устроено то, что легко сломать

- **Картинки и ролики из Blender.** Схема заказа, кнопка света и блок
  направлений сняты скриптами в `brand/blender/` (`scheme.py`, `orb.py`,
  `assembly.py`), результат лежит в `public/scheme`, `public/theme`,
  `public/assembly`. Запуск — в шапке каждого скрипта; нужны Blender 5
  и ffmpeg. Править руками эти файлы бессмысленно: меняется сцена —
  перерисовывается всё, отдельно для тёмной и светлой темы.
- **Движение между кадрами.** И пролёты схемы, и повороты блока устроены
  одинаково: в покое стоит резкий кадр, между кадрами играет ролик,
  который начинается одним кадром и кончается другим. Если ролик
  не успел загрузиться или движение отключено — кадры сменяются наплывом.
  Покачивание блока — те же ролики: начало прямого и конец обратного.
  Длина и частота кадров ролика записаны в `components/Assembly.tsx`
  (`TURN_S`, `FPS`) — при пересъёмке с другими числами поправить и там.
- **Тема по умолчанию — светлая**, какая бы ни стояла в системе (решение
  заказчика 04.10.2026): сервер отдаёт `data-theme="light"`, тёмную
  возвращает загрузочная строка тому, кто выбрал её кнопкой света.
- **Смена темы** идёт волной от кнопки (`lib/theme.ts`). Всё, что зависит
  от темы и грузится картинкой, должно подписаться на `onThemePrepare`
  и заранее загрузить кадр новой темы — иначе под волной будет пусто.
- **Фон** — один шейдер на весь сайт (`components/HeroSilk.tsx`), секции
  управляют им через `data-chapter`. Под схемой и блоком направлений
  фон плоский — так задумано.
- **Анимации** — только прозрачность и трансформ. Заказчик один раз
  уже жаловался, что «всё фризит»; после этого всё тяжёлое убрано.

## Вкус заказчика

- Оценивает результат, а не описание: проще показать дешёвый прототип,
  чем объяснять.
- Перед большой переделкой ждёт вопросов с вариантами и обычно берёт
  рекомендованный.
- Не принимает шаблонные приёмы: пульсирующие точки, бегущие строки,
  гигантское название, шторки на переходах. Эффект — только ради смысла.
- Нравится: предметы из Blender, настоящее движение камеры, живые экраны.
- Коммиты на русском; каждый проход записывается в `BRIEF.md`; в конце
  прохода `main` перематывается на последний коммит.
